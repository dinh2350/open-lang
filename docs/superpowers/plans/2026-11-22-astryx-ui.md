# Astryx UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the whole look of `apps/frontend` with Meta's Astryx design system, stone theme, in light and dark, and remove Tailwind and shadcn.

**Architecture:** An `AppTheme` component wraps Astryx's `<Theme theme={stoneTheme} mode>`. A `ThemeModeProvider` above the router owns the light/dark choice (device default, saved choice wins) and a header `ModeToggle` on every page flips it. Each page is rewritten onto Astryx components with the same text, roles and flows. The old `components/ui`, Tailwind and Radix are deleted last.

**Tech Stack:** React 19, Vite 8, Vitest + Testing Library (jsdom), Playwright, `@astryxdesign/core` and `@astryxdesign/theme-stone` 0.7.17 (beta), `@stylexjs/stylex` 0.19.x (Astryx's peer dependency).

**Spec:** [docs/superpowers/specs/2026-11-22-astryx-ui-design.html](../specs/2026-11-22-astryx-ui-design.html)

## Global Constraints

- Pin `@astryxdesign/core`, `@astryxdesign/theme-stone` and `@astryxdesign/cli` to exactly `0.7.17` (`--save-exact`). Pin `@stylexjs/stylex` exactly too, on the newest `0.19.x`.
- Theme: **stone**, light and dark. Only Astryx styles the UI; Tailwind, shadcn, Radix and class-variance-authority are removed by Task 8.
- Every page keeps its visible text, heading names, routes, roles and flows. Roles, labels, keyboard use and live regions do not get worse.
- The mode toggle shows on **every** page, including sign-in and register. Two states (light or dark). First visit follows the device; after a toggle the saved choice wins. Saved in `localStorage` key `open-lang-theme-mode`, every read and write inside try/catch.
- Existing tests are the contract for behavior, not for how they poke the page. You may rewrite how a test interacts and adjust a query when Astryx adds a second live region. You may not weaken or delete an assertion. The existing e2e specs should pass as they are; change one only if Astryx forces it, and keep it minimal.
- Where an Astryx component cannot keep something the app does today, use, in order: another Astryx component; a swizzled copy (`pnpm exec astryx swizzle <Name>`); a native element styled with Astryx tokens. Log every such exception in the "Exceptions log" at the bottom of this plan.
- Do **not** run `astryx init` against the root `CLAUDE.md` or `AGENTS.md`. Look up component APIs with `pnpm exec astryx component <Name>` and `pnpm exec astryx docs <topic>` instead.
- Self-hosted fonts: `@astryxdesign/theme-stone/fonts.css` ships Figtree as local woff2 files, so import it; no third-party font requests.
- LiveKit's React components stay; only their styling changes.
- No `NOSONAR`, `@ts-ignore`, ESLint or Sonar exclusions, or lowered thresholds.
- End every commit message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Work on a branch: `git switch -c feat/astryx-ui` before Task 1.

## Review Focus

- Storage blocked or throwing (private window): the app still renders and the toggle still switches in memory. Pinned by Task 2.
- A saved value that is not `light` or `dark` (hand-edited or from an older version): ignored, the device default applies. Pinned by Task 2.
- A browser with no `matchMedia`: light, no crash. Pinned by Task 2.
- The chosen mode survives signing in (the route changes, the pages remount). Pinned by Task 3.
- The new header on the signed-out pages adds no second `role="alert"`, so a validation error is still one alert. Pinned by Task 3.
